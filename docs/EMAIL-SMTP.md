# Настройка e-mail уведомлений о обращениях (SMTP)

Форма обратной связи работает всегда: каждое обращение сохраняется в базу
данных и появляется в админ-панели → «Обращения» (`/admin/submissions`).

E-mail уведомление — **дополнительный** канал доставки: письмо о новом
обращении приходит на указанный адрес. Пока SMTP не настроен, сайт честно
сообщает посетителю: «Уведомления на e-mail сейчас не подключены» — никаких
ложных сообщений об отправке нет.

## 1. Какие переменные нужны

Добавьте в `.env` (рядом с `package.json`) и перезапустите приложение:

| Переменная | Пример | Что это |
|---|---|---|
| `SMTP_HOST` | `smtp.yandex.ru` | Сервер исходящей почты |
| `SMTP_PORT` | `465` | 465 — SSL, 587 — STARTTLS |
| `SMTP_USER` | `documentonline.direct@yandex.ru` | Логин SMTP (обычно ящик) |
| `SMTP_PASSWORD` | *(пароль приложения)* | Пароль SMTP. Секрет — не публиковать |
| `SMTP_FROM` | `documentonline.direct@yandex.ru` | Адрес отправителя письма |
| `FEEDBACK_TO_EMAIL` | `documentonline.direct@yandex.ru` | Куда доставлять обращения |
| `SITE_NAME` | `Правовой маршрут` | Название в теме письма (необязательно) |

Код читает именно эти имена переменных (`src/lib/mailer.ts`):
письмо отправляется только когда заданы `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`
и (`FEEDBACK_TO_EMAIL` или `SMTP_USER`).

Шаблон с готовыми строками — в корне проекта: `.env.example`.

## 2. Настройка Яндекс.Почты (адрес documentonline.direct@yandex.ru)

1. Войдите в ящик `documentonline.direct@yandex.ru` на mail.yandex.ru.
2. Создайте **пароль приложения**: настройки Яндекс ID → «Безопасность» →
   «Пароли приложений» → тип «Почта». Яндекс не принимает обычный пароль
   аккаунта для SMTP — нужен именно пароль приложения.
3. Полученный пароль запишите в `SMTP_PASSWORD`.
4. Значения остальных переменных:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=documentonline.direct@yandex.ru
SMTP_FROM=documentonline.direct@yandex.ru
FEEDBACK_TO_EMAIL=documentonline.direct@yandex.ru
```

Порт 465 включает SSL автоматически (`secure: true` в коде). Для 587
используется STARTTLS — код это учитывает.

Похожим образом настраивается любой другой SMTP-провайдер: Mail.ru
(`smtp.mail.ru`, порт 465), ваш доменный ящик у хостера или сторонний
сервис рассылок — меняются только `SMTP_HOST`/`SMTP_PORT`.

## 3. Как проверить, что доставка работает

1. Задайте переменные в `.env`, перезапустите приложение
   (`pm2 restart pravo-site` или `npm run start`).
2. Отправьте тестовое обращение через форму на `/contacts/`.
3. Успешные признаки:
   - на `FEEDBACK_TO_EMAIL` пришло письмо «Обращение с сайта «Правовой маршрут»: …»;
   - в админ-панели → «Обращения» у записи отметка «письмо отправлено»
     (поле `emailSent`).
4. Если письмо не пришло, а обращение сохранено — проверьте папку «Спам»,
   затем переменные `SMTP_HOST/PORT/USER/PASSWORD/FROM/FEEDBACK_TO_EMAIL`
   (частая ошибка: основной пароль аккаунта вместо пароля приложения).

## 4. Безопасность

- `.env` не публикуется в git (исключён в `.gitignore`). Пароль приложения
  не должен попадать в отчёты, скриншоты, логи и клиентский код.
- Секреты передаются только через переменные окружения сервера; в БД и на
  страницу они не выводятся.
- Если пароль скомпрометирован — отзовите его в Яндекс ID и создайте новый,
  затем обновите `SMTP_PASSWORD` и перезапустите приложение.
- Адрес отправителя (`SMTP_FROM`) должен совпадать с `SMTP_USER` или быть его
  псевдонимом, иначе письма будут отклонены провайдером.
