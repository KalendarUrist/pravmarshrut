# Безопасность сайта

Что уже реализовано в коде и что нужно делать вам для поддержания защиты.

---

## 1. Реализовано в проекте

| Требование | Реализация |
|---|---|
| Авторизация администратора | Сессии в БД + httpOnly-cookie (`SameSite=Lax`, `Secure` при HTTPS) |
| Хеширование паролей | scrypt (node:crypto) со случайной солью; пароли не хранятся в открытом виде |
| Защита от перебора пароля | 8 неудачных попыток с одного IP → блокировка входа на 15 минут (журнал в таблице `LoginAttempt`) |
| Защита админ-маршрутов | Серверная проверка сессии в layout админки и в каждом API-обработчике; без сессии — редирект на `/admin/login` или 401 |
| Защита от CSRF | Cookie `SameSite=Lax`; проверка `Origin` против `Host` для всех изменяющих запросов; server actions Next.js с встроенной проверкой источника |
| Защита от SQL-инъекций | Prisma ORM — параметризованные запросы, конкатенации SQL нет |
| Защита от XSS | Весь HTML из редактора проходит санитайзер (allowlist тегов/атрибутов/классов); iframe в контенте запрещён; внешние ссылки получают `rel="nofollow noopener noreferrer"` |
| Загрузка файлов | Проверка магических байтов (не только расширения), allowlist форматов (JPG/PNG/WebP/GIF), лимит размера, случайные имена файлов, раздача только через `/media/{id}` с `nosniff` |
| SVG | Запрещён к загрузке (векторные файлы — классический вектор XSS) |
| Видео | Не загружается на сервер; вставляется embed только с разрешённых платформ (YouTube-nocookie, RuTube, VK, Дзен) с проверкой URL |
| Анти-спам форм | Скрытое honeypot-поле + проверка времени заполнения + лимит 5 обращений в час с одного IP |
| Серверная валидация | Все поля форм проверяются на сервере независимо от клиентской проверки |
| Секреты | Не хранятся в клиентском коде; пароль администратора задаётся только через переменные окружения при сидинге; в репозиторий попадать не должны |
| Безопасные заголовки | `X-Content-Type-Options`, `Strict-Transport-Security` и др. (см. DEPLOY.md, конфиг Caddy) |

## 2. Обязательные действия перед запуском

1. **Смените пароль администратора**, если seed запускался с паролем по умолчанию
   (`ChangeMe2026!`). Инструкция сброса — в docs/INSTALL.md, раздел 4.
2. Убедитесь, что `.env` не попадает в git (проверьте `.gitignore` — строка `.env` уже там;
   при необходимости добавьте).
3. Включите HTTPS (docs/DEPLOY.md, раздел 6) — cookie сессии помечаются `Secure`
   только при HTTPS.
4. Настройте резервное копирование (docs/BACKUP.md).

## 3. Регулярное обслуживание

- Раз в месяц: `apt update && apt upgrade` на сервере; обновления Node.js по security-веткам.
- Раз в квартал: обновление зависимостей сайта
  (`npm outdated`, затем `npm update` и `npm run build` + тесты).
- Проверяйте раздел «Обращения» — спам-записи удаляйте (лимиты обычно отсекают
  ботов, но не гарантируют 100%).
- Следите за логами: `pm2 logs pravo-site`, `journalctl -u caddy`.

## 4. Если требуется жёсткая изоляция

- Ограничьте вход в админку по IP на уровне Caddy:

```
вашдомен.ru {
    @admin path /admin/* /api/admin/* /api/auth/*
    handle @admin {
        @notallowed not remote_ip 1.2.3.4
        respond @notallowed 403
        reverse_proxy localhost:3000
    }
    handle {
        reverse_proxy localhost:3000
    }
}
```

- Для панели допустимо также добавить HTTP Basic Auth на уровне Caddy —
  двухфакторная по сути защита (сначала Basic Auth, затем пароль админки).
